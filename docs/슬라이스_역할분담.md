# FITMATE 슬라이스와 역할 분담

> 슬라이스 하나를 이슈 하나로 발행한다. 제목은 `.github/ISSUE_TEMPLATE/slice.md` 형식을 따른다. 이슈 번호가 정해지기 전이라 `S1`~`S9`로 부른다. 담당자 이름은 팀에서 채운다.

## 전체 보기

| 슬라이스 | 완료하면 할 수 있는 일 | 차단 | 스토리 | 라벨(제안) |
|---|---|---|---|---|
| S1 | 목표를 고르고 추천 루틴 확인하기 | 없음 | 1 | `ready-for-human` |
| S2 | 다른 PC의 친구와 같은 3D 운동방에 입장하기 | S1 | 2, 4 | `ready-for-human` |
| S3 | 카메라 앞에서 유효 횟수와 자세 피드백 받기 | S1 | 3 | `ready-for-human` |
| S4 | 내 실제 움직임을 캐릭터와 친구 화면에서 보기 | S2, S3 | 4 | `ready-for-human` |
| S5 | AI 가이드 시범을 보며 따라 하기 | S2 | 3 | `ready-for-human` |
| S6 | 친구 캐릭터를 클릭해 응원 주고받기 | S2 | 6 | `ready-for-agent` |
| S7 | 친구와 관계없이 내 루틴을 끝까지 진행하기 | S2, S3 | 5 | `ready-for-human` |
| S8 | 내 결과와 팀 경험치 변화 확인하기 | S7 | 7, 8 | `ready-for-human` |
| S9 | 1회차 결과로 2회차 추천받고 다시 입장하기 | S8 | 7 | `ready-for-human` |

스택과 기준값이 미정이라 대부분 `ready-for-human`이다. S6은 스택이 정해지면 에이전트에게 맡길 수 있다.

```text
S1 (착수 가능)
├── S2 ──┬── S5
│        ├── S6
│        ├── S4
│        └── S7 ── S8 ── S9
└── S3 ──┴── S4, S7
```

**같이 진행할 수 있는 묶음:** S1 → S2·S3 동시 → S4·S5·S6·S7 동시 → S8 → S9

**커버리지:** 사용자 스토리 1~8이 모두 한 슬라이스 이상에 담겼고, 모든 슬라이스가 스토리를 하나 이상 참조한다.

## 직군별 역할

| 직군 | 맡는 일 | 주요 슬라이스 |
|---|---|---|
| PM | 미결 항목 결정, 임시값 승인, P0 통합 테스트 판정, 발표 범위 안내 | 전체 |
| 디자인 | 오류 상태 화면, 응원 UI, 2회차 추천 영역, 기성 캐릭터·공간 에셋 선정 | S1, S2, S5, S6, S7, S9 |
| 프론트엔드 | 화면 구현, 상태 전환, 오류 안내, 서버 연동 | S1~S9 전체 |
| 백엔드(실시간) | 운동방 입퇴장, 참가자 상태, 동작 정보 전달, 응원 전달, 끊김과 재접속 | S2, S4, S6, S7 |
| 백엔드(데이터·배포) | 참가자 식별, 루틴 저장, 수행 기록, 결과 조회, 경험치 적립, 2회차 저장, 배포 | S1, S2, S6, S7, S8, S9 |
| AI | 동작 인식, 유효 판정, 자세 피드백, 추천과 난도 규칙 설계 | S1, S3, S4, S8, S9 |
| 3D (프론트 중 한 명) | 운동 공간, 캐릭터 렌더링, 동작 반영, AI 가이드 | S2, S3, S4, S5, S6 |

문서에 PM, 디자이너, 프론트, AI 담당은 나오지만 백엔드와 3D 담당은 "개발팀"으로만 적혀 있다. 아래 분담은 제안이며 이름은 팀에서 채운다.

**분담 원칙 (제안)**

- PoC를 만든 사람이 있으면 그 파트를 우선 맡는다. 담당자는 아직 확인되지 않았다.
- 백엔드가 2명이면 실시간과 데이터·배포로 나눈다. 1명이면 실시간을 먼저 한다.
- 3D는 브라우저 화면과 붙어 있어 프론트 중 한 명이 맡는다. 프론트에 여유가 없으면 PM과 범위를 다시 상의한다.
- 캐릭터와 공간은 직접 모델링하지 않고 뼈대(리깅)가 있는 기성 에셋을 쓴다.
- 백엔드가 3D를 겸하지 않는다. 실시간과 3D는 S2와 S4에 함께 걸려 있어 한 사람에게 몰리면 위험하다.
- 인식 결과를 캐릭터 움직임으로 바꾸는 경계는, 동작 정보 형식을 S3에서 AI와 3D 담당이 함께 정하고 변환은 3D 담당이 맡는다.

## 착수 전 결정 (슬라이스 아님)

| 인원수와 정원, 운동방과 팀의 관계 | PM | S2, S8 |
| 운동 목록과 인식 가능 여부 | PM, AI | S1, S3 |
| 영상 처리 위치와 카메라 안내 문구 | PM, 개발팀 | S3 |
| 시간 기반 운동의 판정 방식 | AI, PM | S3 |
| 휴식과 일시정지 규칙 | PM | S7 |
| 자세 결과 형식, 경험치 산식 | PM, AI | S8 |
| 난도 기준, 수행 부족 시 유지 또는 하향 | AI, PM | S9 |

## S1. [Feat] Slice 01 목표를 고르고 추천 루틴 확인하기

### 상위 (Parent)
PRD (발행 후 번호 기입)

### 구현 내용 (What to build)
목표 선택부터 루틴 확인까지 배포된 화면에서 동작시킨다. 저장소, 배포, 프론트와 서버 연결을 가장 먼저 한 번씩 밟기 위한 슬라이스다.

**공통 계약**
- 루틴: 회차, 목표, 운동 목록(운동 ID, 이름, 순서, 목표 횟수 또는 시간, 세트), 상태.
- 추천 상태는 준비, 완료, 불가 셋이다. 불가일 때 운동 목록을 보내지 않는다.

**백엔드(데이터·배포):** 저장소와 배포 구성, 운동 데이터, 루틴 생성과 저장 API.
**프론트엔드:** 목표 선택, 추천 로딩, 루틴 확인 화면과 상태 3종.
**AI:** 목표별 기본 루틴 규칙. 인식 검증된 운동만 사용한다.
**디자인:** 추천 불가 상태 시안.
**PM:** 운동 목록 확정.

**통합 검증:** 배포 URL에서 목표 4종을 각각 선택해 루틴이 표시되는지 본다.

### 완료 시 보이는 것 (Demo)
배포된 화면에서 목표를 고르면 추천 운동 2~3개와 수행량이 나온다.

### 완료 조건 (Acceptance Criteria)
- [ ] 목표를 선택하지 않으면 다음 단계로 넘어가지 않는다.
- [ ] 목표를 고르면 운동 2~3개와 순서, 수행량, 세트가 표시된다.
- [ ] 추천 불가 상태에서 없는 운동 목록을 보여주지 않는다.
- [ ] 정해진 루틴을 쓰는 경우 화면 문구가 개인화 범위를 과장하지 않는다.

### 차단 관계 (Blocked by)
없음 — 즉시 착수 가능 (스택 결정 후)

### 해당 사용자 스토리 (User Stories Addressed)
사용자 스토리 1

## S2. [Feat] Slice 02 다른 PC의 친구와 같은 3D 운동방에 입장하기

### 상위 (Parent)
PRD (발행 후 번호 기입)

### 구현 내용 (What to build)
닉네임과 캐릭터를 정해 지정 운동방에 들어가면 서로 다른 PC에서 서로의 캐릭터와 상태가 보이게 한다. 실시간 통신과 3D 공간의 뼈대를 여기서 정한다.

**공통 계약**
- 참가자: 임시 식별값, 닉네임, 캐릭터.
- 방 상태 이벤트: 입장, 퇴장, 현재 운동, 진행 상태, 연결 상태.

**백엔드(실시간):** 입퇴장 처리, 방 상태 실시간 전달.
**백엔드(데이터·배포):** 임시 식별 발급, 지정 운동방 데이터.
**프론트엔드:** 닉네임·캐릭터 설정, 대기 화면, 입장 실패 안내와 재시도.
**3D:** 실제 3D 공간과 참가자 캐릭터 배치, 닉네임·운동·상태 표시.
**디자인:** 기성 캐릭터와 공간 에셋 선정, 상태 구분 표현.
**PM:** 인원수와 정원 초과 동작 확정.

**통합 검증:** PC 두 대 이상으로 접속해 서로의 표시를 대조한다.

### 완료 시 보이는 것 (Demo)
다른 PC에서 들어온 친구의 캐릭터와 닉네임, 현재 운동이 내 화면의 3D 공간에 나타난다.

### 완료 조건 (Acceptance Criteria)
- [ ] 로그인과 초대 없이 지정 운동방에 입장한다.
- [ ] 서로 다른 PC의 화면에서 참가자별 닉네임, 운동, 상태가 일치한다.
- [ ] 운동방이 2D 배경 이미지가 아닌 3D 공간으로 표시된다.
- [ ] 같은 닉네임의 참가자가 있어도 서로 다른 참가자로 구분된다.
- [ ] 연결에 실패하면 실패 안내와 재시도 수단이 나온다.

### 차단 관계 (Blocked by)
S1 (배포 구성과 루틴 계약)

### 해당 사용자 스토리 (User Stories Addressed)
사용자 스토리 2, 4

## S3. [Feat] Slice 03 카메라 앞에서 유효 횟수와 자세 피드백 받기

### 상위 (Parent)
PRD (발행 후 번호 기입)

### 구현 내용 (What to build)
혼자서도 동작하는 인식 경로를 먼저 만든다. 가장 위험한 기술이라 일찍 실제 환경에서 검증한다.

**공통 계약**
- 동작 정보 출력 형식: S4의 캐릭터 반영이 이 형식을 입력으로 쓴다.
- 판정 결과: 유효, 기준 미달, 판정 불가. 수행 기록: 운동 ID, 인정 횟수, 실제 소요 시간, 자세 판정 결과.

**AI:** 동작 인식, 운동별 판정 규칙, 시간 기반 운동 처리, 중복 카운트 방지, 정상·미흡 동작 촬영 테스트.
**프론트엔드:** 권한 요청, 권한 거부와 장치 오류 안내, 인식 불가 안내, 횟수와 피드백 표시.
**3D:** AI 담당과 동작 정보 형식 합의.
**PM:** 임시 판정 기준 승인, 카메라 안내 문구 확정.

**통합 검증:** 촬영 사례로 카운트와 미카운트를 대조하고, 가림·어두움·화면 이탈을 직접 시험한다.

### 완료 시 보이는 것 (Demo)
카메라 앞에서 운동하면 바른 동작만 숫자가 오르고, 미달 동작에는 자세 안내가 뜬다.

### 완료 조건 (Acceptance Criteria)
- [ ] 정상 동작은 횟수가 오르고 기준 미달 동작은 오르지 않으며 피드백이 뜬다.
- [ ] 한 동작이 두 번 카운트되지 않는다.
- [ ] 권한 거부, 장치 없음, 인식 불가 동안 횟수와 자세 결과가 새로 생기지 않는다.
- [ ] 권한 거부 시 재설정과 재시도 방법이 표시된다.
- [ ] 처리 방식이 확정되기 전에는 영상 저장 여부를 단정하는 문구가 나오지 않는다.

### 차단 관계 (Blocked by)
S1 (운동 ID와 수행량 계약)

### 해당 사용자 스토리 (User Stories Addressed)
사용자 스토리 3

## S4. [Feat] Slice 04 내 실제 움직임을 캐릭터와 친구 화면에서 보기

### 상위 (Parent)
PRD (발행 후 번호 기입)

### 구현 내용 (What to build)
S3의 동작 정보를 내 3D 캐릭터에 반영하고 친구 화면까지 전달한다. FITMATE의 핵심 차별점이다.

**공통 계약**
- 동작 이벤트: 참가자 식별값, 방 식별값, 현재 운동, 동작 정보.
- 동작 정보가 없으면 움직임을 만들어 내지 않고 인식 불가 또는 연결 불안정 상태로 둔다.

**3D:** 동작 정보를 팔·다리·몸통 움직임으로 변환.
**백엔드(실시간):** 동작 이벤트 실시간 전달.
**AI:** 동작 정보 품질과 전송 빈도 조정.
**프론트엔드:** 3D 화면과 인식·연결 상태 연결.

**통합 검증:** PC 여러 대에서 움직여 보고, 응답속도와 FPS를 재서 PM에게 합격 수치를 제안한다.

### 완료 시 보이는 것 (Demo)
내가 팔을 들면 내 캐릭터와 친구 화면의 내 캐릭터가 같이 팔을 든다.

### 완료 조건 (Acceptance Criteria)
- [ ] 실제 팔·다리·몸통 움직임이 본인 캐릭터에서 구별되어 보인다.
- [ ] 같은 움직임이 다른 PC의 해당 캐릭터에서도 보인다.
- [ ] 인식이 끊기거나 네트워크가 끊기면 반복 애니메이션이나 임의 움직임이 나오지 않는다.
- [ ] 카메라를 허용하지 않은 참가자의 동작 정보는 공유되지 않는다.

### 차단 관계 (Blocked by)
S2 (운동방, 캐릭터), S3 (동작 정보 형식)

### 해당 사용자 스토리 (User Stories Addressed)
사용자 스토리 4

## S5. [Feat] Slice 05 AI 가이드 시범을 보며 따라 하기

### 상위 (Parent)
PRD (발행 후 번호 기입)

### 구현 내용 (What to build)
현재 운동의 올바른 동작을 별도 3D 캐릭터로 시범 보인다. 인식과 독립적으로 만들 수 있어 S3, S4와 병렬로 진행한다.

**공통 계약**
- 운동 ID로 가이드 시범 동작을 찾는다. 없으면 시범 없음 상태를 반환한다.

**3D:** 운동별 가이드 동작과 캐릭터.
**프론트엔드:** 대기, 운동, 전환 화면에 시범 연결.
**디자인:** 참가자 캐릭터와 구별되는 가이드 외형.

## S8. [Feat] Slice 08 내 결과와 팀 경험치 변화 확인하기

### 상위 (Parent)
PRD (발행 후 번호 기입)

### 구현 내용 (What to build)
운동을 마치면 확정된 기록으로 개인 결과를 보여주고 팀 경험치를 적립한다.

**공통 계약**
- 결과: 운동별 유효 횟수, 운동 시간, 측정 가능한 자세 결과. 미측정 값은 미측정으로 전달한다.
- 경험치 변화: 적립 경험치, 누적 경험치. 운동 기록 ID 하나에 한 번만 적립한다.

**백엔드(데이터·배포):** 결과 조회, 경험치 적립과 중복 방지.
**프론트엔드:** 결과 화면.
**AI:** 자세 결과 집계 형식.
**PM:** 자세 결과 형식, 임시 경험치 산식, 레벨 표시 여부, 팀 정의 확정.

**통합 검증:** 같은 기록을 다시 제출해 경험치를 대조하고, 두 참가자의 결과가 섞이지 않는지 본다.

### 완료 시 보이는 것 (Demo)

### 완료 조건 (Acceptance Criteria)
- [ ] 결과 화면의 값이 저장된 수행 기록과 일치한다.
- [ ] 다른 참가자의 기록이 내 결과나 친구별 점수로 표시되지 않는다.
- [ ] 같은 운동 기록을 다시 제출해도 경험치가 한 번만 적립된다.
- [ ] 합의된 기준이 없으면 레벨 상승이 표시되지 않는다.

### 차단 관계 (Blocked by)

## S9. [Feat] Slice 09 1회차 결과로 2회차 추천받고 다시 입장하기

### 상위 (Parent)
PRD (발행 후 번호 기입)

### 구현 내용 (What to build)
1회차 기록을 평가해 2회차 루틴과 변경 이유를 보여주고, 그 루틴으로 다시 운동방에 들어간다. 시연의 마지막 장면이다.

**공통 계약**
- 2회차 추천: 근거 운동 기록 ID, 새 루틴, 조정 유형(상향, 유지, 분석 불가), 조정 사유.
- 같은 입력에는 같은 조정 결과가 나온다.

**AI:** 수행 평가와 난도 규칙 설계, 사례별 검증.
**백엔드(데이터·배포):** 추천 저장과 조회 API.
**프론트엔드:** 결과 화면의 추천 영역, 생성 중과 분석 불가 상태, 2회차 입장.
**디자인:** 추천과 변경 이유 영역 시안 (현재 와이어프레임 텍스트에 없음).
**PM:** 판정 기준과 증가 폭, 수행 부족 시 처리 승인.

**통합 검증:** 좋은 사례, 부족한 사례, 근거 부족 사례를 넣어 끝까지 시연한다.

### 완료 시 보이는 것 (Demo)
1회차를 잘 마치면 수행량이 오른 2회차 루틴과 그 이유가 나오고, 바로 다시 입장할 수 있다.

### 완료 조건 (Acceptance Criteria)
- [ ] 좋은 사례에서 난도가 오른 루틴과 근거 기록, 변경 이유가 표시된다.
- [ ] 부족한 사례에서 난도가 오르지 않고 이유가 표시된다.
- [ ] 근거가 부족한 사례는 분석 불가로 안내되고 난도가 오르지 않는다.
- [ ] 추천은 해당 참가자 본인에게만 표시된다.
- [ ] 2회차 입장 후 운동방에서 추천과 같은 순서와 수행량으로 진행된다.

### 차단 관계 (Blocked by)
S8 (결과 화면과 확정 기록)
