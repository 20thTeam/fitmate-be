# FITMATE 기능명세서

> 원본: PM 매니패스트 문서(2026-11-03 플로우 기준). `확인 필요`는 원본에 없고 문서 간 대조에서 추가한 항목이다. 원본의 S01~S04는 화면 이름으로 바꿔 적었으며, 대응 관계는 추정이다.

요구사항 9개, 기능 22개, 상세 2개. 기능마다 같은 9칸을 채우므로 빈칸이 바로 보인다.

## 프로덕트 정책

### 1. 해커톤 시연 범위

- 시연은 목표 선택, 추천, 실제 운동, 3D 공간의 친구 연결, 개인 결과·팀 경험치 변화·다음 추천을 끝까지 동작시키는 데스크톱 웹 MVP이다.
- 친구 초대와 정식 회원가입은 원래 서비스에 있으나 시연에서 구현하지 않으며, 이 사실을 문서와 발표에서 명시한다.
- 긴 온보딩, 별도 운동 테스트, 팀 리그·랭킹, 복잡한 보상은 제외한다.
- 수익 모델은 시연 시점에 언급하지 않고 향후 발표에 추가한다.

### 2. 유효 횟수 인정

- 정상 동작은 포함하고 기준 미달 동작은 제외하며 자세 피드백을 제공한다.
- 판정 불가는 미카운트 또는 판정 보류로 처리하고 허위 기록하지 않는다.
- 운동별 관절 규칙·임계값은 개발팀이 검증해 PM이 승인하며, 시연용 임시 기준을 쓴 뒤 교체한다.
- 새로 촬영한 정상·미흡 동작 사례로 검증하고 인식 실패 조건을 기록한다.

### 3. 다음 회차 난도 조절

- 충분히 정확하게 수행했으면 점진적으로 높이고, 부족하면 일괄 상향하지 않는다.
- 근거가 불충분하면 현재 루틴을 유지하거나 재측정을 안내한다.
- '잘했다' 판정, 상향 요소, 증량폭, 안전 상한은 AI 담당이 설계·검증해 PM이 승인하며 시연용 임시 기준을 먼저 적용한다.
- 2회차 추천에는 근거가 된 1회차 기록과 변경 이유를 함께 보여준다.

### 4. 카메라 및 개인정보

- 카메라 권한은 사용자가 직접 허용한다.
- 식별은 임시 ID 또는 세션, 닉네임, 캐릭터 선택 결과만 사용하는 방향으로 한다.
- 원본 영상 처리 위치는 미정이다(기기 내 분석, 동작 정보만 전송, 원본 전송 중 선택).
- 권한 거부나 장치 없음이면 인식 불가를 안내하고 재설정·재시도 방법을 제공한다.

### 5. 서비스 표현 및 홍보 문구

- 특정 부위 지방 제거나 의료적 효과를 보장한다고 표현하지 않는다.
- 정해진 루틴을 쓰면 'AI' 문구로 개인화 범위를 과장하지 않는다.
- 기술 검증 데모 수치를 제품 성능으로 홍보하지 않는다.
- 자동 애니메이션이나 가짜 기록을 실제 수행 결과로 표현하지 않는다.
- 유주영은 기획용 페르소나이므로 실제 사용자 사례로 소개하지 않는다.

### 6. 미정 사항 임시값 처리

- 미정 항목을 임의로 구현 사양으로 바꾸지 않는다.
- 임시값이 필요하면 임시 가정, 사유, 영향 화면, 승인 필요 여부를 기록해 PM과 확인한다.
- 휴식 길이 같은 초 단위 규칙은 개발자가 임의로 넣지 않는다.
- PM은 무엇이 일어나야 하는지, 개발자는 어떻게 만들지, 디자이너는 어떻게 보일지를 정한다.
- 정확도·응답속도·FPS 합격 기준은 개발팀이 제안하고 PM이 승인한다.

## 요구사항 1. 운동 목표 선택 및 루틴 추천

사용자가 목표 하나를 선택하고, 첫 회차에 수행할 운동 2~3개와 순서·횟수 또는 시간·세트를 추천받는 영역이다. 별도 사전 운동 테스트 없이 시작하며 특정 부위 지방 감소를 약속하는 추천은 포함하지 않는다.

### 기능 1.1 운동 목표 선택

사용자가 첫 화면에서 체중 감량·자세 개선·근력 강화·체력 증진 중 목표 하나를 선택한다. 선택값은 이번 회차의 루틴 추천에 쓰이며 신체 정보 입력과 사전 운동 테스트는 포함하지 않는다.

- **근거:** 홈트 입문자가 복잡한 탐색 없이 운동 목적을 정하고 곧바로 시작하게 한다.
- **화면:** 1

| 슬롯 | 내용 |
|---|---|
| 선행조건 | · 사용자는 회원가입이나 사전 테스트 없이 데스크톱 웹에 접속한 상태이다. |
| 트리거 | · 사용자가 첫 화면에서 목표 하나를 선택하고 추천 단계로 진행한다. |
| 동작 | · 선택한 운동 목표를 현재 회차의 추천 입력으로 전달한다. |
| 결과 | · 선택한 목표는 추천 화면에서 사용할 수 있는 이번 회차의 값으로 유지된다. |
| 예외 | · 목표를 선택하지 않으면 추천으로 진행하지 않는다. |
| 표시 | · 선택지는 네 가지 목표로 표시한다.<br>· 선택 전 상태와 선택한 상태를 구별해 보여준다. |
| 권한 | · 정식 계정이 없는 사용자도 목표를 선택할 수 있다. |
| 규칙 | · 네 가지 목표 중 한 가지를 선택한다.<br>· 이번 시연에서는 사전 운동 테스트를 요구하지 않는다. |
| 데이터 | · 선택 목표는 네 값 중 하나이며 이번 회차 추천과 연결된다. |

### 기능 1.2 목표별 첫 운동 추천

선택한 목표로 첫 회차 운동 2~3개와 순서·횟수 또는 시간·세트를 제공한다. 사전 테스트 없이 기본 루틴에서 시작하며, 운동 목록과 추가 신체 정보 활용은 확정 전까지 필수 조건으로 두지 않는다.

- **근거:** 어떤 운동을 얼마나 할지 혼자 찾지 않아도 바로 시작하게 한다.
- **화면:** 2

| 슬롯 | 내용 |
|---|---|
| 선행조건 | · 사용자가 목표 하나를 선택한 상태이다.<br>· 추천 가능한 운동은 시연에서 수행과 인식이 가능한 운동이어야 한다. |
| 트리거 | · 목표 선택 후 루틴 추천 단계에 진입하면 추천을 생성한다. |
| 동작 | · 선택한 목표로 첫 회차 운동 2~3개와 순서·횟수 또는 시간·세트를 구성한다.<br>· 추천 내용을 루틴 확인 화면에 전달한다. |
| 결과 | · 생성된 루틴은 선택 목표와 연결되어 운동방에서도 같은 순서와 수행량으로 사용된다. |
| 예외 | · 추천 불가 조건을 정의하고 추천 불가 시 대체 안내 상태를 보여준다. |
| 표시 | · 추천 준비, 추천 완료, 추천 불가 상태를 구분해 보여준다. |
| 권한 | _원본에 없음_ |
| 규칙 | · 1회차는 사전 체력 테스트 없이 기본 루틴으로 시작한다.<br>· 목표별로 실제 인식 가능한 운동만 제시한다.<br>· 목표별로 정해진 루틴이면 'AI' 문구로 개인화 범위를 과장하지 않는다. |
| 데이터 | · 루틴은 회차, 선택 목표, 운동 ID·이름, 순서, 목표 횟수 또는 시간, 세트로 구성된다. |
| **확인 필요** | · 운동 목록이 미정이다. 인식 검증을 거친 운동만 넣어야 한다.<br>· 와이어프레임의 난이도·주요 부위·예상 시간은 데이터 항목에 없다. 넣을지 정해야 한다.<br>· 플로우에 추천 불가 분기가 없다. |

### 기능 1.3 추천 루틴 확인 및 운동방 입장

추천된 오늘의 루틴을 확인하고 운동방으로 입장한다. 운동 2~3개와 순서, 동작별 횟수/시간, 세트를 보여주며 루틴 변경은 범위에 포함하지 않는다.

- **근거:** 오늘 할 운동과 수행량을 이해하고 바로 시작하게 한다.
- **화면:** 3

| 슬롯 | 내용 |
|---|---|
| 선행조건 | · 목표별 첫 운동 추천이 생성된 상태이다. |
| 트리거 | · 루틴 확인 후 운동방 입장 버튼을 누른다. |
| 동작 | · 사용자가 루틴을 확인한 뒤 운동방에 입장한다. |
| 결과 | · 이번 회차 루틴과 운동 순서를 운동 화면에 전달한다.<br>· 순서와 수행량이 명확하게 제시되어야 완료이다. |
| 예외 | · 추천이 준비 중이거나 생성되지 않았으면 없는 운동 목록을 보여주지 않는다. |
| 표시 | · 추천 운동 2~3개, 진행 순서, 동작별 횟수/시간, 세트를 표시한다.<br>· 필수 상태는 추천 준비, 추천 완료, 추천 불가·대체 안내이다. |
| 권한 | · 로그인 없이 이용할 수 있다. |
| 규칙 | · 운동방에 전달하는 루틴은 사용자가 확인한 순서·횟수 또는 시간·세트와 일치한다. |
| 데이터 | · 확인 화면의 루틴은 해당 사용자의 목표와 첫 회차 운동 ID·순서·수행량을 조회한다. |

## 요구사항 2. 바로 시작 입장 및 사용자 식별

시연에서 회원가입과 친구 초대 없이 지정된 운동방에 바로 입장하고, 임시 ID 또는 세션·닉네임·캐릭터로 사용자를 구분하는 영역이다. 원래 서비스에는 초대와 회원가입이 있으나 이번 시연에서는 구현하지 않는다.

### 기능 2.1 지정 운동방 바로 입장

추천 루틴 확인 뒤 로그인이나 초대 없이 미리 정한 운동방에 들어간다. 같은 방의 실제 참가자가 식별되어야 한다.

- **근거:** 초대·회원가입 없이 짧게 시작해 핵심 경험을 끝까지 동작시키는 것이 우선이다.
- **화면:** 4→5

| 슬롯 | 내용 |
|---|---|
| 선행조건 | · 사용자가 추천 루틴을 확인한 상태이다.<br>· 입장할 운동방은 미리 지정되어 있다. |
| 트리거 | · 추천 루틴 화면에서 운동방 입장 조작을 한다. |
| 동작 | · 초대나 로그인 절차 없이 지정된 운동방에 입장한다.<br>· 같은 방의 다른 참가자들과 함께 표시된다. |
| 결과 | · 입장 직후 내 캐릭터, 다른 참가자, 현재 운동이 표시된다.<br>· 같은 방의 실제 참여자가 구별된다. |
| 예외 | · 운동방에 연결할 수 없으면 입장 실패를 알리고 다시 시도하게 한다. |
| 표시 | · 입장 후 본인과 같은 방의 실제 참가자를 구별해 보여준다. |
| 권한 | · 로그인이나 초대 없이 지정된 운동방에 누구나 입장할 수 있다. |
| 규칙 | · 참가자는 미리 정해진 운동방에 가입 절차 없이 입장한다.<br>· 서로 다른 PC의 2~5명이 같은 방에서 함께 운동하는 흐름을 검증한다. |
| 데이터 | _원본에 없음_ |
| **확인 필요** | · 정원 초과 시 동작이 정의되어 있지 않다.<br>· 인원수 표기가 문서마다 다르다(2~5명, 친구 2~5명, 친구 4~5명, PC 4~5대).<br>· 플로우에 입장 실패 분기가 없다. |

### 기능 2.2 임시 사용자 식별 및 닉네임·캐릭터

정식 회원가입 없이 시연 운동방에 참가하고 닉네임과 캐릭터로 구별된다. 임시 식별값은 운동 기록·응원 대상·다음 회차 추천을 연결하는 데 쓴다.

- **근거:** 회원가입 없이도 친구를 식별하고 같은 사용자의 기록을 결과 화면과 연결해야 한다.
- **화면:** 4

| 슬롯 | 내용 |
|---|---|
| 선행조건 | · 처음 접속해 아직 식별 정보가 없는 상태이다. |
| 트리거 | · 처음 접속하거나 운동방에 입장할 때 식별 정보를 준비한다. |
| 동작 | · 접속 시 임시 ID 또는 세션을 부여한다.<br>· 닉네임과 캐릭터 선택 결과를 식별 정보에 연결한다. |
| 결과 | · 참가자 구분, 응원 대상 식별, 동일 사용자의 기록 연결에 식별 정보를 사용한다. |

| 표시 | · 닉네임과 캐릭터는 같은 방의 다른 참가자에게 표시된다. |
| 권한 | · 정식 계정이 없어도 임시 참가자로 입장할 수 있다.<br>· 자신의 기록만 본인의 결과 및 다음 회차 추천으로 조회한다. |
| 규칙 | · 개인정보는 최소한으로 처리한다. |
| 데이터 | · 사용자 식별은 임시 ID 또는 세션, 닉네임, 캐릭터 선택 결과를 담는다. |
| **확인 필요** | · 5일 자체 테스트 동안 임시 식별을 어떻게 유지할지 정의가 없다. 기기나 세션이 바뀌면 기록이 끊길 수 있다. |

## 요구사항 3. 카메라 동작 인식 및 유효 횟수

허용한 카메라 영상에서 동작을 인식해 유효 횟수와 짧은 자세 교정 피드백을 제공하는 영역이다. 기준 미달 동작은 유효 횟수에 넣지 않으며 모델과 판정식은 개발팀이 설계한다.

### 기능 3.1 카메라 권한 허용

사용자가 카메라 사용을 직접 허용해 동작 인식과 캐릭터 반영을 시작한다. 원본 영상의 서버 전송 여부는 미정이다.

- **근거:** 카메라 영상은 개인정보 우려가 있어 직접 허용과 최소 정보 처리가 필요하다.
- **화면:** 6

| 슬롯 | 내용 |
|---|---|

| 트리거 | · 운동 시작을 위해 카메라가 필요한 시점에 권한을 요청한다. |
| 동작 | · 사용자가 브라우저 권한 요청에서 카메라를 직접 허용한다. |
| 결과 | · 허용하면 영상에서 동작 정보를 얻어 동작 인식을 시작한다. |
| 예외 | · 거부하거나 장치가 없으면 인식을 시작하지 않고 다시 시도하는 방법을 안내한다. |
| 표시 | _원본에 없음_ |
| 권한 | · 직접 허용한 경우에만 본인 영상을 이용해 운동을 인식한다. |
| 규칙 | · 원본 영상의 처리 위치와 전송 범위는 확정 전까지 단정하지 않는다. |
| 데이터 | _원본에 없음_ |
| **확인 필요** | · 와이어프레임 문구 '이 운동방 내에서만 사용되며 저장되지 않습니다'가 이 규칙과 충돌한다.<br>· 플로우에 거부·취소 분기가 없다. |

### 기능 3.2 유효 횟수 카운트

운동별 유효 조건을 충족한 동작만 수행 횟수에 반영한다. 판정 불가와 기준 미달은 더하지 않으며 모델과 임계값은 확정하지 않는다.

- **근거:** 실제로 운동해야 의미 있는 서비스이므로 정확히 수행한 동작만 센다.
- **화면:** 7

| 슬롯 | 내용 |
|---|---|
| 선행조건 | · 카메라 권한이 허용되고 관절이 인식되는 상태이다.<br>· 추천 루틴의 현재 운동이 선택되어 있다. |
| 트리거 | · 운동 동작을 수행하면 동작 정보가 들어와 판정을 시작한다. |
| 동작 | · 운동별 관절 규칙과 임계값으로 유효 여부를 판정한다.<br>· 유효하면 횟수를 올리고 기준 미달이면 올리지 않는다.<br>· 같은 동작이 중복 카운트되지 않게 한다. |
| 결과 | · 유효 횟수, 운동 상태, 교정 피드백, 분석용 기록을 출력한다.<br>· 정상 동작은 반영되고 기준 미달 동작은 미카운트·피드백 처리된다. |
| 예외 | · 판정이 불가능하면 미카운트 또는 판정 보류로 처리하고 허위 기록하지 않는다.<br>· 관절 인식 불가 상황에서는 근거 없는 카운트를 하지 않는다. |
| 표시 | · 가이드 동작을 따라 운동하는 동안 본인의 유효 횟수를 운동 화면에서 확인한다. |
| 권한 | _원본에 없음_ |
| 규칙 | · 기준 미달 동작은 유효 횟수에 포함하지 않는다. |
| 데이터 | · 수행 기록은 운동 ID, 인정 횟수, 실제 소요 시간, 자세 판정 결과를 담는다. |
| **확인 필요** | · 플랭크 같은 시간 기반 운동의 유효 판정 기준이 없다. 와이어프레임은 '30초'와 '30회'가 섞여 있다. |

### 기능 3.3 자세 교정 피드백

부정확한 동작에 짧은 자세 안내를 보여준다. 안내가 뜬 동작은 유효 횟수에 반영되지 않는다.

- **근거:** 기준 미달 이유를 알고 자세를 고쳐 다시 유효하게 수행하도록 돕는다.

| 트리거 | · 동작이 기준에 미달한다고 판정될 때 발생한다. |

| 예외 | _원본에 없음_ |

| 권한 | _원본에 없음_ |
| 규칙 | · 측정 가능한 자세 결과만 안내하고 근거 없는 피드백은 하지 않는다. |
| 데이터 | _원본에 없음_ |
| **확인 필요** | · 자세 점수(87점 등)의 산식이 없다. 점수를 표시할지 정해야 한다. |

## 요구사항 4. 실시간 운동방 및 친구 상태 공유

서로 다른 PC의 사용자와 친구 2~5명이 같은 실제 3D 운동 공간에서 캐릭터·닉네임·현재 운동·진행 상태·실제 움직임을 확인하는 영역이다. 운동 종류와 시작·종료 시점이 달라도 각자의 운동은 독립적으로 이어지며, 2D 배경 이미지만 쓰는 방식은 포함하지 않는다.

### 기능 4.1 참가자 캐릭터·닉네임·운동 이름 표시

같은 3D 공간의 본인·친구 캐릭터를 닉네임·현재 운동·진행 상태로 구별해 본다. 캐릭터 외형과 공간 연출은 디자인 협의 대상이다.

- **근거:** 각자 다른 운동을 해도 같은 공간에서 실제 친구의 움직임과 상태를 보는 느낌이 핵심 경험이다.
- **성공 기준:** 서로 다른 PC의 사용자와 친구 2~5명이 같은 3D 운동방에서 실제 참가자의 닉네임·운동·상태를 서로 맞게 확인한다.
- **화면:** 5, 7

| 슬롯 | 내용 |
|---|---|
| 선행조건 | · 사용자와 친구는 같은 운동방에 실제로 입장한 상태이다. |
| 트리거 | · 참가자가 입장하거나 운동과 진행 상태가 바뀔 때 캐릭터 표시를 갱신한다. |
| 동작 | · 참가자별 식별값·현재 운동·진행 상태를 같은 3D 공간의 해당 캐릭터와 연결한다. |
| 결과 | · 본인과 친구 2~5명의 캐릭터가 같은 3D 공간에 배치되고 닉네임·현재 운동·진행 상태가 구별된다. |
| 예외 | · 정보가 도착하지 않았거나 연결이 불안정하면 다른 참가자의 이름이나 상태를 대신 표시하지 않는다. |
| 표시 | · 평면 이미지 배경이 아닌 실제 3D 공간을 표시한다.<br>· 본인과 친구 캐릭터는 비슷한 크기로 닉네임·현재 운동·진행 상태를 함께 표시한다. |
| 권한 | · 같은 운동방 참가자만 서로의 운동 상태와 캐릭터를 확인한다. |
| 규칙 | · 실제 3D 운동 공간과 3D 참가자 캐릭터를 제공한다.<br>· 캐릭터 외형·공간 구성·렌더링 엔진은 문서에서 특정하지 않는다. |
| 데이터 | · 참가자 표시는 방 식별값·사용자 식별값·캐릭터·닉네임·현재 운동·진행 상태에 연결된다. |

### 기능 4.2 친구 운동 상태 표시

같은 방의 친구마다 운동 중인지, 대기하거나 종료했는지 구별한다. 색상과 효과는 디자인 협의 대상이다.

- **근거:** 친구가 먼저 끝났는지, 쉬는 중인지 알아야 같은 공간에 있다는 느낌이 생긴다.
- **화면:** 5, 7

| 슬롯 | 내용 |
|---|---|
| 선행조건 | · 친구가 같은 3D 운동방의 실제 참가자로 식별된 상태이다. |
| 트리거 | · 친구의 운동 시작·종료·대기 또는 연결 상태가 변경될 때 표시를 갱신한다. |
| 동작 | · 친구의 실제 진행 상태를 3D 캐릭터에 대응시켜 운동 중인 친구를 구분한다. |
| 결과 | · 친구의 운동 중 여부가 다른 참가자의 진행을 바꾸지 않은 채 표시된다. |
| 예외 | · 연결이 끊기면 마지막 운동 중 상태를 현재 상태로 단정하지 않고 연결 불안정을 구분한다. |
| 표시 | · 운동 중인 친구는 대기·종료 중인 친구와 시각적으로 구별된다. |
| 권한 | · 같은 운동방 참가자만 다른 참가자의 상태를 확인할 수 있다. |
| 규칙 | · 참가자별 진행은 서로 독립적이며 상태 표현은 실제 기록에 기반한다. |
| 데이터 | · 친구 상태는 방과 참가자 식별값·현재 운동·진행 상태·연결 상태에 연결된다. |

### 기능 4.3 참가자별 독립 운동 진행

참가자가 서로 다른 운동을 각자 원하는 시점에 시작하고 종료한다. 한 사람의 휴식·지연·종료·입퇴장이 다른 참가자의 진행을 바꾸지 않는다.

- **근거:** 개인 루틴이 독립적이어서 일정과 목표가 달라도 함께하는 느낌을 줄 수 있어야 한다.
- **성공 기준:** 한 명이 먼저 운동을 마쳐도 다른 친구의 운동은 계속된다.
- **화면:** 5, 7, 8

| 슬롯 | 내용 |
|---|---|
| 선행조건 | · 참가자가 운동방에 입장해 있다. |
| 트리거 | · 참가자가 각자 시작 조작을 하거나 운동을 종료하거나 방에 입장·퇴장한다. |
| 동작 | · 각 참가자의 시작·진행·종료는 서로 독립적으로 처리한다. |
| 결과 | · 한 명만 먼저 운동해도 친구 화면에서 움직임이 보이고 나머지는 대기할 수 있다.<br>· 늦게 시작하거나 먼저 끝나도 나머지 참가자의 진행에 영향이 없다. |
| 예외 | · 다른 참가자의 입장·퇴장으로 내 운동이 중단되지 않게 처리한다. |
| 표시 | · 각 참가자의 캐릭터는 해당 참가자의 현재 운동과 진행 상태를 따로 표시한다. |
| 권한 | _원본에 없음_ |
| 규칙 | · 참가자마다 다른 운동과 다른 시작 시점을 가질 수 있다.<br>· 운동 종료 후 다른 참가자와 관계없이 내 결과 화면으로 이동할 수 있다. |
| 데이터 | _원본에 없음_ |

### 기능 4.4 접속 끊김·재접속 안내

자신 또는 친구의 연결이 불안정할 때 누구의 문제인지 구별하고 복구 안내를 받는다. 친구의 끊김 때문에 내 운동을 중단하지 않는다.

- **근거:** 다중 PC 실시간 연결은 끊김 위험이 있어 원인을 알고 복구할 수 있어야 한다.
- **화면:** 7

| 슬롯 | 내용 |
|---|---|

| 권한 | · 같은 방의 참가자만 서로의 연결 상태를 확인한다. |

## 요구사항 5. AI 운동 가이드 및 캐릭터 반영

웹캠에서 인식된 팔·다리·몸통 움직임이 본인의 3D 캐릭터에 반영되고 친구에게 공유되는 영역이다. 별도의 3D AI 가이드 캐릭터가 올바른 동작을 시범 보이며, 단순 반복 애니메이션을 실제 동작으로 대체하지 않는다.

### 기능 5.1 AI 운동 가이드 시범

현재 추천 운동의 올바른 동작을 본인이나 친구와 구분되는 별도 3D AI 가이드 캐릭터의 시범으로 확인한다. 실제 움직임을 대신 수행한 것으로 기록하지 않는다.

- **근거:** 운동 방법을 혼자 찾지 않고 Just Dance처럼 가이드 동작을 따라 하게 한다.
- **화면:** 5, 7, 8

| 동작 | · 현재 운동과 맞는 올바른 동작을 별도 3D AI 가이드 캐릭터로 시범 보인다. |
| 결과 | · 3D 공간의 가이드와 자신의 캐릭터를 구분해 올바른 동작을 따라 할 수 있다. |
| 예외 | · 시범을 불러올 수 없으면 다른 운동의 시범을 잘못 보여주지 않는다. |
| 표시 | · 가이드 캐릭터는 사용자와 친구의 캐릭터와 구별되게 표시한다. |
| 권한 | · 참가자는 자기 현재 운동에 맞는 가이드를 볼 수 있다. |
| 규칙 | · 가이드 시범은 실제 동작이나 유효 횟수로 간주하지 않는다. |
| 데이터 | · 가이드 시범은 현재 운동 식별값에 대응하는 운동 동작과 연결된다. |
| **확인 필요** | · 대기 화면 문구는 '시범 영상'인데 명세는 3D 캐릭터 시범이다. |

### 기능 5.2 내 움직임 캐릭터 반영 및 친구 화면 공유

웹캠 앞의 실제 팔·다리·몸통 움직임을 자신의 3D 캐릭터에서 보고, 같은 방의 친구가 실시간으로 확인한다. 단순 반복 애니메이션으로 대체하지 않는다.

- **근거:** 사용자 동작이 화면과 연결되고 친구가 실제 움직임을 보는 것이 핵심 경험이다.

| 표시 | · 캐릭터는 실제 팔·다리·몸통 움직임을 구별 가능하게 표현한다.<br>· 친구 화면에서도 그 사용자의 캐릭터 움직임을 확인한다. |

| 데이터 | · 동작 상태는 참가자 식별값·방 식별값·현재 운동과 연결된다. |

## 요구사항 6. 친구 캐릭터 클릭 응원

운동 중 친구 캐릭터를 클릭해 응원 리액션을 보내고 받는 영역이다. 대상 식별과 연타 처리는 개발팀 책임이며 음성 통화는 범위에서 제외한다.

### 기능 6.1 친구 캐릭터 클릭 응원

3D 친구 캐릭터를 클릭해 해당 친구에게 실시간 응원 메시지 또는 리액션을 보낸다. 음성 통화와 복잡한 보상은 포함하지 않는다.

- **근거:** 서로의 움직임과 응원으로 다시 참여할 동기를 얻는 것이 중단 문제를 줄이는 핵심이다.
- **성공 기준:** A PC에서 B 친구를 클릭해 보낸 응원이 B 측에 표시되고 다른 친구에게 잘못 전달되지 않는다.
- **화면:** 7

| 슬롯 | 내용 |
|---|---|
| 선행조건 | · 보내는 사람과 받는 친구가 같은 운동방에 있다.<br>· 친구 캐릭터가 클릭 가능한 상태로 표시된다. |

| 결과 | · 지정한 친구 화면에 응원 리액션이 표시된다.<br>· 응원 이벤트에 보낸 사람, 받은 사람, 리액션, 이벤트 시각이 기록된다. |
| 예외 | · 중복·연타 클릭은 개발팀이 처리 방식을 설계한다.<br>· 대상이 연결 불안정이거나 퇴장한 경우의 처리는 개발팀이 설계한다. |
| 표시 | · 보낸 사람에게 클릭한 대상 친구를 확인할 수 있게 보여준다.<br>· 받은 친구에게 도착한 응원을 실시간으로 표시한다. |
| 권한 | · 같은 운동방 참가자는 서로 응원을 보낼 수 있다. |
| 규칙 | · 응원 대상이 다른 친구로 잘못 전달되지 않아야 한다. |
| 데이터 | · 응원 이벤트는 보낸 사람, 받은 사람, 리액션, 이벤트 시각을 담는다. |
| **확인 필요** | · 운동 진행 화면 텍스트에 응원 요소가 없다. 화면 설계가 필요하다. |

## 요구사항 7. 운동 진행 흐름 및 예외 처리

입장·대기, 운동 진행, 운동 간 전환·휴식, 운동 종료로 이어지는 개인 운동 상태와 카메라·네트워크·인식·추천 오류 등 반드시 처리할 예외를 다루는 영역이다. 휴식 시간·일시정지·강제 종료 등 세부 규칙은 미정이며 개발자가 임의로 확정하지 않는다.

### 기능 7.1 내 운동 상태 전환

운동을 시작하고 루틴의 각 운동을 진행한 뒤 결과를 확인하도록 개인 운동 상태를 전환한다. 친구의 진행은 본인의 상태를 바꾸지 않는다.

- **근거:** 연속적 경험이라는 방향은 유지하되 세부 전환은 PM·디자이너·프론트·AI 담당이 함께 확정해야 한다.
- **화면:** 5, 7, 8

| 슬롯 | 내용 |
|---|---|
| 선행조건 | · 추천 루틴을 가지고 운동방에 입장한 상태이다. |
| 트리거 | · 시작 조작, 목표 달성, 사용자 조작, 카메라 권한·장치 상태 변화로 전환한다. |
| 동작 | · 입장·대기: 친구들과 가이드·루틴을 보여주고 시작 조작으로 운동 진행으로 전환한다.<br>· 운동 진행: 움직임·유효 횟수·피드백을 보여주고 목표 달성 또는 사용자 조작으로 전환한다.<br>· 운동 간 전환·휴식: 다음 동작을 안내한다.<br>· 운동 종료: 기록을 정리하고 결과 화면으로 이동한다.<br>· 카메라 오류: 카운트를 보류하고 안내·재시도를 제공한다. |
| 결과 | · 내 운동은 친구의 상태와 무관하게 시작할 수 있다.<br>· 운동 종료 시 기록이 정리되어 결과 화면으로 이동한다. |
| 예외 | · 카메라 오류 시 카운트를 보류하고 권한과 장치가 정상화되면 복귀한다. |
| 표시 | · 상태별 화면 구성은 디자이너가 시안으로 제안한다.<br>· 휴식 시간·일시정지 버튼·강제 종료의 실제 UI는 확정하지 않는다. |
| 권한 | · 해당 참가자만 본인의 운동을 시작하고 상태를 조작한다. |
| 규칙 | · 입장·대기에서 시작 조작으로 운동 진행 상태로 전환한다.<br>· 카메라 오류 동안에는 유효 횟수를 추가하지 않는다.<br>· 휴식 길이·다음 운동 전환·일시정지·강제 종료·결과 이동 조건은 확정 전까지 임의로 정하지 않는다. |
| 데이터 | · 개인 운동 상태는 참가자 식별값·회차·현재 운동·수행 기록과 연결된다. |
| **확인 필요** | · 와이어프레임의 '일시정지' 버튼과 '08초' 카운트다운이 이 규칙과 충돌한다. |

### 기능 7.2 카메라 권한 거부·장치 오류 안내

- **근거:** 카메라 없이는 인식과 판정이 불가능하므로 복구 방법을 알아야 한다.

| 트리거 | · 카메라 권한 거부나 장치 없음이 감지될 때이다. |

| 예외 | · 재설정 후에도 사용할 수 없으면 오류 상태를 유지하고 허위 횟수를 기록하지 않는다. |
| 표시 | · 오류 이유와 재시도 방법을 안내 문구로 보여준다. |
| 권한 | · 권한을 직접 허용받지 못한 동안에는 동작 인식을 실행하지 않는다. |
| 규칙 | · 카메라를 사용할 수 없는 동안에는 유효 횟수와 자세 결과를 새로 생성하지 않는다. |
| 데이터 | · 오류 상태는 진행 중 운동과 연결되며 이전에 확정한 유효 횟수와 구분된다. |
| **확인 필요** | · 전용 오류 화면이 와이어프레임에 없다. |

### 기능 7.3 관절 인식 불가 안내

관절을 충분히 인식하지 못해 판정할 수 없을 때 원인을 확인하고 다시 인식하도록 안내한다. 화면 밖 이동·가림·어두움에서는 근거 없는 카운트나 평가를 만들지 않는다.

- **근거:** 인식 근거 없이 횟수가 오르면 허위 기록이 되어 결과 분석과 추천의 신뢰가 무너진다.
- **화면:** 7

| 슬롯 | 내용 |
|---|---|
| 선행조건 | · 카메라 사용을 허용하고 현재 운동을 진행하고 있다. |
| 트리거 | · 화면을 벗어나거나 가려지거나 어두워져 관절을 충분히 인식하지 못할 때 안내한다. |

| 표시 | · 인식되지 않음을 알리고 화면과 조명을 조정해 다시 시도하도록 안내한다. |

## 요구사항 9. 팀 운동 성장 및 경험치

운동을 마친 뒤 실제 수행 결과와 연결된 팀 경험치 변화를 확인하고 팀원의 성취가 팀 성장에 반영되는 영역이다. 레벨 상승은 기준이 합의된 경우에만 표시하며 리그·랭킹·복잡한 보상은 포함하지 않는다.

### 기능 9.1 팀 경험치 및 성장 확인

운동을 마친 뒤 개인 결과와 그 운동으로 달라진 팀 경험치를 확인한다. 경험치 산식과 팀 소속 기준은 팀의 결정으로 남긴다.

- **근거:** 혼자 중단하기 쉬운 사용자가 공동 성장으로 다시 참여할 동기를 얻게 한다.

|---|---|
